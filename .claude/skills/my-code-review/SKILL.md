# emoji-quiz コードレビュー

対象は、引数で指定されたファイル/ブランチ/PR。指定が無ければ `git diff main...HEAD` と未コミットの差分（`git diff HEAD`）。
差分が無い場合は `src/` 全体を対象にする。

## 手順

1. 対象の差分を取得し、変更ファイルを全文読む（差分だけで判断しない）。
2. `README.md` の「仕様」「技術仕様」「仮に決めた点」を読み、変更が仕様に沿うか確認する。
3. `npm run build`（`tsc --noEmit && vite build`）を実行し、型エラー・未使用変数（`noUnusedLocals/Parameters` が有効）が無いことを確認する。テストは未整備（`npm test` は未実装）なので、挙動は読んで検証する。
4. 下記の観点でレビューし、「出力形式」でまとめる。

## レビュー観点

### 1. 仕様との整合（README.md）
- 4択で正解がちょうど1つ。選択肢に同じ絵文字が重複しない（`unicode` で比較）。
- 1ゲーム10問（`QUESTION_COUNT`）、同じ絵文字を正解に2回出さない。
- 正解のみスコア+1。正解/不正解で別の効果音が鳴る。終了時にスコア（10点満点）と「Play again」。
- 「✕」ボタンで中断→確認ダイアログ（Keep playing / Quit）→タイトルへ。中断後にタイマー（次問への遷移 `NEXT_DELAY_MS` など）や状態が残って誤動作しない。
- 回答後の二重タップで、スコアが二重加算されたり次問が二重に進んだりしない。
- 仕様を変える場合は README の該当箇所も更新されているか。

### 2. データ（emoji.ts / CSV）
- `emoji-v18.csv` は出題用、`emoji-v18-master.csv` は絞り込み前の原本。出題コードが master を参照していないか。
- CSV パーサーはダブルクォート内のカンマ・改行・BOM を扱う。変更時は `"kiss: woman, man"` のような行で壊れないか。
- 絵文字は肌色・ZWJ 等で複数コードポイントになる。`string.length` や `[...str]` で1文字扱いしていないか。識別は `unicode` 列を使う。
- 選択肢の絵文字が紛らわしい（見た目が同一/ほぼ同一）出題を悪化させる変更でないか。

### 3. TypeScript
- `strict` 前提。`any`、不要な `as`、`!`（non-null assertion）の濫用が無いか。`querySelector` 結果の null 扱いは妥当か。
- `quiz.ts` は純粋ロジックとして DOM に依存させない。UI の責務は `main.ts`、音は `sound.ts` に閉じる。
- 乱数（`Math.random`）の使い方。シャッフルは Fisher-Yates、`sort(() => Math.random() - 0.5)` は不可。
- 外部依存を安易に増やしていないか（devDependencies は typescript / vite のみの小さな構成）。

### 4. DOM / UI（main.ts）
- ユーザー由来でない固定データでも、HTML は `innerHTML` ではなく `textContent` / `el()` ヘルパーで組む（既存方針）。`innerHTML` が増えていないか。
- 画面遷移で古い要素・イベントリスナー・`setTimeout` が残らない。
- 装飾要素（浮遊絵文字・紙吹雪）は `aria-hidden="true"`。ボタンに適切なラベル（絵文字ボタンは `aria-label` 等）があるか。
- 確認ダイアログのフォーカス、Escape/背景タップの扱いが一貫しているか。

### 4-2. アクセシビリティ（WCAG 2.x レベル A、README 技術仕様・CLAUDE.md）
UI を触る変更では必ず確認し、満たせていなければ 🔴 必須修正として扱う。
- 1.1.1: 絵文字のみのボタン・アイコンにアクセシブルな名前がある。装飾は `aria-hidden="true"`。ただし答えが分かる名前（出題文と同じ name）を付けていない。
- 1.3.1 / 4.1.2: `<button>` 等の適切な要素を使い、名前・役割・状態が支援技術に伝わる（`div` + click は不可）。
- 1.4.1: 正誤などを色だけで示していない（文言・アイコン併用）。
- 1.4.2 / 音: 3秒を超える自動再生音が無い。効果音だけで情報を伝えていない。
- 2.1.1 / 2.1.2: すべての操作がキーボードで可能で、フォーカスが閉じ込められない。ダイアログはフォーカス移動と復帰がある。
- 2.2.2: 5秒を超えて自動で動くもの（浮遊絵文字・紙吹雪等）に停止手段か `prefers-reduced-motion` 対応がある。
- 2.4.2 / 3.1.1: `<title>` と `<html lang>` が維持されている。
- 3.3.2: 入力欄を追加する場合はラベルがある。
- 状態通知: `aria-live` 領域が画面生成時ではなく常設されているか（要確認事項として扱ってよい）。

### 5. 効果音（sound.ts）
- `AudioContext` は Start ボタン押下（ユーザー操作）内で `initSound()` を呼ぶ必要がある。操作前に生成・再生していないか。
- `suspended` 状態の `resume()`、`ctx` 未初期化時に例外を出さないこと。
- 音量が大きすぎない（現状 0.15〜0.2）。ノードの接続・停止（`osc.stop`）で漏れが無いか。
- 音声ファイルを追加していないか（Web Audio 合成の方針）。

### 6. CSS / モバイル（style.css, index.html）
- 縦向きスマホが前提。PC・横向き対応は不要だが、狭い幅（320px 前後）で崩れない・横スクロールしない。
- タップ領域が十分（目安 44px 以上）。`viewport` meta、ダブルタップ拡大や iOS Safari の `100vh` 問題への配慮。
- アニメーションが重すぎない。可能なら `prefers-reduced-motion` を尊重。
- 絵文字のフォントフォールバック指定が壊れていないか。

### 7. ビルド・デプロイ
- `vite.config.ts` の `base: "./"` を維持（GitHub Pages のサブパスで動くため）。絶対パス（`/assets/...`、`/foo.csv`）を直書きしていないか。
- CSV は `?raw` でバンドルされる。実行時 `fetch` で別ファイルを読む変更は、dist に含まれるか確認する。
- `.github/workflows/build.yml` を変えた場合: `package-lock.json` は `.gitignore` 対象のため `npm install`（`npm ci` 不可）、deploy は main のみ、権限は最小限。
- 秘密情報やデバッグ用 `console.log` を含めていない。

## 出力形式

指摘は重要度別に、日本語で簡潔にまとめる。各指摘に `[ファイル:行](パス#L行)` 形式の参照、問題の理由、修正案を付ける。

```
## レビュー結果
概要: 1〜2文で変更内容と全体評価。
ビルド: `npm run build` の結果（成功/失敗と要点）

### 🔴 必須修正（バグ・仕様違反・ビルド失敗）
### 🟡 推奨（保守性・UX・アクセシビリティ・パフォーマンス）
### 🟢 提案（任意の改善・好み）
### ✅ 良かった点（あれば短く）
```

- 指摘が無い区分は省略する。憶測で指摘せず、コードを読んで確認できたものだけを書く。確証が無いものは「要確認」と明記する。
- 既存コードのスタイル（コメントは日本語で「なぜ」を書く、2スペースインデント、ダブルクォート）に合わせた修正案にする。
- ユーザーが依頼しない限り、勝手にコードを修正しない。指摘のみ行う。
